# 성경암송 72구절 — 설계

작성일: 2026-11-23 · 상태: **최종안(사용자 승인 대기)**
검토: Codex 설계 리뷰 2회(조건 반영 완료), Codex 연습 화면 제안 + 2차 합의, 독립 빌더 체크.

## 1. 의도와 이유

조원들이 **함께** 사랑의교회 「성경암송 72구절」(네비게이토 주제별 암송 체계 기반)을 외우게 한다.
통독 앱에는 이미 조 단위 진도, 조원 현황, 기도제목이 있다. 그래서 같은 조 안에서 "이번 주 구절"을 함께 외우고, 서로의 진도를 보며 모임에서 확인하는 흐름을 만든다.

**사용자가 결정한 것**
- 확인 방식: 앱은 **외우는 연습을 돕고**, "외웠어요"는 **각자 스스로 체크**한다. 실제 확인은 조 모임에서 서로 해준다. 타이핑 시험은 넣지 않는다.
- 조원 현황: **전체 현황판**으로 공개한다("다들 성인이라 자기가 알아서 체크").
- 저장 구조: **접근 A** — 개인 프로필에 원본, 조원 문서에 사본.
- 저작권 관련: 음성(사랑의교회 음원)과 사이트 디자인은 쓰지 않는다. 출처는 표시한다.
- 연습 화면: "더 고도화"한다(→ 6장, Codex와 합의한 안).

## 2. 목표 / 비목표 / 실패 기준

**목표**
- 72구절(6묶음 × 소주제 6개 × 2구절)을 앱 안에서 읽고, 연습하고, 체크하고, 복습할 수 있다.
- 조 모드에서는 조 전체가 같은 "이번 주 구절"을 보고 조원 전체 현황판을 본다. 혼자 모드에서는 같은 화면을 각자 속도로 쓴다.
- 외운 기록은 혼자↔조 전환, 조 이동, 전체 초기화 후에도 유지된다.
- 출처 표시: "출처: 사랑의교회 성경암송 72구절 (네비게이토)".

**비목표**: 음성 인식, 타이핑 시험, 알림·리마인더, 다른 암송 목록, 점수·배지·순위 강조, 사랑의교회 음원·디자인.

**실패 기준 (동작해도 실패)**
- 연습 화면이 작은 글씨나 복잡한 조작 때문에 중장년층이 쓰기 어려운 것.
- 외운 기록이 모드 전환·조 이동·초기화 후 사라지는 것.
- 개인 메모·형광펜이 조원에게 노출되는 것.
- 통독(기존 기능)의 화면·동기화가 느려지거나 깨지는 것.
- 연습 중에 동기화 때문에 화면이 다시 그려져 가림 상태나 현재 위치를 잃는 것.

## 3. 제약

- 빌드 도구 없는 vanilla JS, GitHub Pages 배포. 기존 패턴을 그대로 쓴다: `render()` 라우터, `state.view`, `VIEW_DEPTH` 뒤로가기, `renderFromSync`, `verseFontSize()`.
- Firestore 보안 규칙은 **사용자가 Firebase 콘솔에 붙여넣어 배포**한다(`FIRESTORE_RULES.md` 방식). 반드시 **규칙 먼저 배포 → 앱 배포** 순서로 한다. 앱이 먼저 나가면 조 생성·참가·사본 쓰기·암송 시작일 저장이 거부된다.
- 본문은 앱의 개역개정(`bible/GAE.js`)을 쓴다. 72개 참조는 모두 앱 데이터에 키가 있고, 사이트 본문과도 일치한다(띄어쓰기·문장부호 제외, 스크립트로 확인함).
- `users/{uid}`는 본인만 읽을 수 있다. 조원끼리 서로의 프로필을 읽게 열면 메모·형광펜이 노출되므로 금지한다.

## 4. 접근 방식

| | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | 원본 `users/{uid}.memorized` + 현재 조의 조원 문서에 사본 | 어디서나 기록 유지. 조원 문서는 이미 실시간 구독 중이라 현황판에 드는 추가 비용이 거의 없음 | 사본을 맞추는 로직이 필요 |
| B | 조원 문서에만 저장 | 가장 단순 | 혼자 모드를 못 쓰고, 조를 옮기면 기록 소실 |
| C | 조원끼리 서로의 프로필 읽기 허용 | 저장 위치가 한 곳 | 메모·형광펜까지 노출 — 제외 |

## 5. 데이터와 동기화

### 5.1 72구절 목록 — `memorize-data.js` (신규, 정적, 약 15KB)
```js
window.MEMORIZE72 = {
  source: '사랑의교회 성경암송 72구절 (네비게이토)',
  sets: [ { id:'A', title:'새로운 삶', topics: [
    { title:'중심되신 그리스도', verses: [
      { id:'고후5:17', label:'고린도후서 5:17', keys:['고후5:17'], chunks:null },
      { id:'갈2:20', label:'갈라디아서 2:20', keys:['갈2:20'], chunks:[12, 25] } ] }, ...6개 ] }, ...6묶음 ] };
```
- 목록·순서는 **부록 A**를 따른다. 원자료는 사랑의교회 페이지 A~F에서 추출했다. 원본 추출본은 구현 시 `scripts/`에 생성 스크립트와 함께 커밋한다.
- `id`는 첫 절 키다. 72개가 서로 다른지 테스트로 확인한다. 여러 절이면 `keys`에 모두 넣는다(예: `빌4:6,7` → 2개, `마22:37~39` → 3개).
- 사이트 데이터 보정: D묶음 고후 9:6,7의 소주제가 사이트에 "금주의 말씀 -->"로 잘못 나와 있다 → **"후히 드릴 것"**으로 고친다.
- `chunks`는 어절 단위 분할 위치(어절 인덱스 배열)다. **15어절 이하는 `null`(나누지 않음)이고, 15어절 초과는 45개**다.
  - 생성 순서: ① 여러 절이고 15어절을 넘으면 절 경계로 먼저 나눈다. ② 그래도 15어절을 넘는 부분은 연결어미(~니/~고/~며/~요/~라/~되/~나 등) 뒤에서 8~14어절 단위로 나눈다.
  - 휴리스틱으로 초안을 만든 뒤 **45개 모두 사람이 검토**한다(검토표를 PR에 포함).
  - 테스트: 부분을 이어 붙인 결과가 원문과 공백·문장부호까지 같아야 한다.

### 5.2 외운 기록 — 쓰기는 원본 한 곳, 사본은 '맞춰 쓰기'
- **원본** `users/{uid}.memorized = { [id]: 'YYYY-MM-DD' }`. 값은 외운 날짜다.
  - 체크: `set({ memorized: { [id]: 날짜 } }, { merge: true })` — 문서가 없어도 동작하고 해당 키만 병합된다.
  - 해제: `update(new FieldPath('memorized', id), FieldValue.delete())`. 문서가 없어서 실패하면 이미 해제된 것으로 처리한다. 그 밖의 실패는 체크 표시를 되돌리고 토스트로 알린다.
  - `memorized`는 기존 전체 맵 저장 경로(`pushMapKeys` 대체 경로, `pushSoloData`)로 **절대 쓰지 않는다**.
  - 로컬 캐시는 `state.memorized`(localStorage)다.
- **원본 구독**: 지금은 조 모드에서 프로필 구독이 끊긴다. 이를 바꿔 **혼자·조 모드 모두에서 프로필 구독을 유지**한다.
  - `watchProfile`은 `includeMetadataChanges: true`로 구독하고 `metadata`를 콜백에 넘긴다.
  - 초기 로드, 4초 타임아웃 뒤 늦게 온 프로필, 실시간 스냅샷 모두 같은 적용 함수를 쓴다.
  - 서버가 확인한 원본에 없는 키는 해제된 것으로 반영한다. 캐시에서 아직 확인되지 않은 상태와 진짜 빈 원본은 구별한다.
- **사본** `groups/{g}/members/{uid}.memorized`(같은 형태). **현재 조(`state.groupRef.groupId`) 하나만** 관리한다.
  - **맞춰 쓰기**: 다음 계기가 생기면 **서버 트랜잭션**을 연다.
    - 계기: 서버가 확인한 원본 스냅샷(`!fromCache && !hasPendingWrites`), 현재 조 변경, 조원 데이터 준비 완료, 재접속(메타데이터만 바뀐 서버 확인 포함).
    - 트랜잭션 안에서 원본 문서와 내 조원 문서를 다시 읽어 `memorized`가 다를 때만 `{ memorized: 정규화한 원본, updatedAt: serverTimestamp() }`로 교체한다.
    - 조원 문서가 서버에 없으면(나간 조) 아무것도 하지 않는다.
    - 두 기기가 엇갈려 써도 트랜잭션이 최신 원본으로 맞춘다.
  - 정규화: 등록된 72개 id와 `YYYY-MM-DD` 형식의 값만 남긴다.
  - 실패 처리: 일시 오류는 간격을 두고 재시도한다. `permission-denied`는 로그인·권한 상태가 바뀌었을 때 다시 확인한다. 오프라인 동안 사본이 늦는 것은 허용하지만, 재접속하면 자동으로 복구된다.
- **조 생성·참가**:
  - 새 조원 문서에는 현재 UID로 **서버가 확인한** 원본을 넣는다. 아직 확인 전이면 `memorized`를 생략하고 맞춰 쓰기에 맡긴다.
  - 기존 조원이 다시 들어오는 경로의 이름 변경은 `updateMyMember`로 분리한다. 이때 현재의 `displayName` 갱신과 조건부 `plan` 갱신을 모두 보존한다.
- **조 이동·나가기**:
  - 나가지 않고 다른 조에 참가하는 기존 흐름은 이전 조의 조원 문서를 남긴다(통독 readDays와 같은 기존 동작). 그래서 이전 조원들은 **마지막 암송 현황을 계속 보게 된다.** 참가 화면에 이 사실을 안내한다.
  - 명시적인 **조 나가기**는 조원 문서 삭제가 성공한 경우에만 완료로 처리한다. 지금은 실패를 무시하고 조 포인터를 비우는데, 이를 고친다.
- **전체 초기화**: 외운 기록과 혼자 모드 암송 시작일을 로컬·서버 양쪽에서 **보존**한다(형광펜·메모와 같은 정책). 확인 문구에도 이 내용을 넣는다.
- **복습 일정**은 기기에만 저장한다(6.5). Firestore에는 저장하지 않는다.

### 5.3 암송 시작일과 주차
- 조 모드: `groups/{g}.memoStart: 'YYYY-MM-DD'`. **조장만** 설정하고 바꿀 수 있다.
- 혼자 모드: `users/{uid}.memoStart`. 사용자가 이번 주 탭에서 **[암송 시작하기]**를 누를 때 오늘 날짜로 확정한다(설정에서 변경 가능).
- 주차 계산: **달력 날짜 차이**로 계산한다. 시작일 당일부터 7일이 1주차이고 1~36주다. 주 2구절, 즉 소주제 하나씩이다.

| 상태 | 이번 주 탭 표시 |
|---|---|
| 조 시작일 미설정 | 조원에게는 "조장이 암송 시작일을 정하면 이번 주 구절이 표시돼요" + 전체 72로 자유 연습 유도. 조장에게는 시작일 설정 버튼 |
| 시작일이 미래 | "M월 D일부터 시작해요" + 1주차 구절 미리보기 |
| 1~36주 | 해당 소주제 2구절 |
| 36주 이후 | "72구절 한 바퀴를 마쳤어요 · 외운 구절 N/72" + 전체 72 탭을 기본으로 |

### 5.4 Firestore 규칙 변경 (`firestore.rules`, `FIRESTORE_RULES.md` 모두 갱신)
- `members/{uid}` create: 허용 키에 `memorized`를 추가한다. update: `affectedKeys().hasOnly([... 'memorized'])`.
  - 공통 검증: `!('memorized' in data) || (data.memorized is map && data.memorized.size() <= 72)`.
  - 기존 `validMemberData`(displayName·readDays)와 `updatedAt == request.time` 조건은 유지한다.
- `groups/{g}` 조장 update: 허용 키에 `memoStart`를 추가한다. 선택 필드이고, 형식은 `^\d{4}-\d{2}-\d{2}$`다. 이 필드가 없는 기존 조도 이름·통독 시작일 변경이 통과해야 한다. 그룹 생성 payload에는 넣지 않는다.
- `users/{uid}`: 변경 없음.
- id·값 형식은 규칙에서 검증하지 않고 화면 집계에서 정규화한다. 권한과 크기 제한은 규칙 테스트로 확인한다(8장).

## 6. 화면 (UX)

### 6.1 진입점
- **헤더**에 '암송' 아이콘과 라벨을 혼자·조 모드 모두에 추가한다. `.header-actions`에도 `flex-wrap`을 적용한다. 지금은 이게 없어서 아이콘 5개가 넘칠 수 있다. 좁은 화면, 큰 글씨, 긴 조 이름에서 확인한다.
- **메인(통독) 화면**의 읽음·공유·복사 버튼 아래에 작은 카드를 둔다. 예: "📖 12주차 암송 · 고후 5:17 외 1 · 0/2 외움 →". 문구는 5.3의 상태에 맞춘다. 통독을 마친 뒤 자연스럽게 이어지게 하려는 것이고, 본문 위에는 두지 않는다.
- 암송 화면은 `state.view = 'memorize'`이고, 뒤로가기 깊이는 1이다.

### 6.2 탭 구성
**[이번 주] [전체 72] [조원 현황]** — 조원 현황은 조 모드에서만. 화면 맨 아래에 출처를 표시한다.

### 6.3 연습 카드 — 흐름 (Codex 합의안)
근거는 인출 연습(가리고 떠올리기)이 반복 읽기보다 오래 기억에 남는다는 점, 그리고 의미 단위로 나누면 한 번에 붙잡아야 할 분량이 준다는 점이다.

1. **읽기**: 처음에는 소주제, 주소, 본문 전체를 보여준다. 본문은 통독 글자 크기를 따른다. 안내 한 줄: "주소 → 본문 → 주소 순서로 소리 내어 말해 보세요."
2. **[가리고 말하기]**: 큰 기본 버튼이다. 누르면 주소와 소주제만 남기고 본문을 가린다. 가린 상태에서 쓰는 버튼:
   - **[힌트]**: 처음 누르면 현재 부분의 첫 어절, 이후 누를 때마다 한 어절씩 더 보인다. 부분 끝까지 보이면 비활성화되고, 부분을 옮기거나 **[다시 가리기]**를 누르면 초기화된다.
   - **[본문 보기]**: 대조용으로 전체를 공개한다.
   - **[다시 가리기]**
3. **[나눠 연습]**: `chunks`가 있는 구절에만 보인다. "2 / 3 부분" 형태로 이전·다음 부분을 오가고, 같은 가리기·힌트·본문 보기를 쓴다. 맨 아래 **[처음부터 말하기]**는 전체 가리기로 돌아간다.
4. ~~**[🔊 듣기]**~~ — **삭제 (사용자 결정, 2026-11-24 연습 카드 체험 후).** 이번 주 카드 안의 소주제 줄도 위 주차 줄과 겹쳐 삭제(전체 72·복습 카드에는 유지).
5. **[○ 외웠어요]**: 연습 버튼들과 떨어진 위치에 둔다. 상태는 글자와 `aria-pressed`로 나타낸다("✓ 외웠어요 · 누르면 취소"). 체크하면 토스트를 띄운다. 연습 횟수와 관계없이 언제든 체크하거나 해제할 수 있다.

```
 12주차 · A. 새로운 삶 — 중심되신 그리스도
 ┌──────────────────────────────────┐
 │ 갈라디아서 2:20                    │
 │ 내가 그리스도와 함께 십자가에        │
 │ 못박혔나니 그런즉 …(전체)            │
 │ 주소 → 본문 → 주소 순서로 말해 보세요 │
 │ [        가리고 말하기        ]      │
 │ [          나눠 연습          ]      │
 │                                      │
 │ [ ○ 외웠어요 ]                        │
 └──────────────────────────────────┘
 ─ 가린 상태(나눠 연습 2/3) ─
 │ 갈라디아서 2:20 · 2 / 3 부분          │
 │ 이제는 내가 …                         │  ← 힌트 2번 누름
 │ [ 힌트 ]  [ 본문 보기 ]  [다시 가리기] │
 │ [ ‹ 이전 부분 ]      [ 다음 부분 › ]  │

```
- 버튼은 최소 높이 48px로, 글자로 동작을 쓰고, 큰 글씨에서는 줄바꿈을 허용한다. 가린 본문은 화면 낭독기에서도 숨긴다. PC에서는 키보드로 조작할 수 있다.
- **연습 상태 보존**: 동기화 때문에 다시 그려져도 펼친 카드, 가림·힌트 공개량, 현재 부분을 유지한다. 연습 상태는 `volatile`에 두고, 다시 그릴 때 복원한다.

### 6.4 전체 72 · 조원 현황
- **전체 72**: 6묶음을 접이식으로 보여준다(묶음 제목 + "8/12"). 그 안에 소주제별 2구절과 체크 표시가 있다. 구절을 누르면 같은 화면 안에서 연습 카드가 펼쳐진다. 이번 주 소주제는 강조한다.
- **조원 현황(전체 공개)**: 조원별 행 — 이름, "N/72", 이번 주 2구절 ✓/○(이번 주차가 있을 때만). 행을 누르면 그 조원의 묶음별 구절 상태가 펼쳐진다. 정렬은 기존 '조원 진도' 화면처럼 진도순이다. 72칸 격자는 넣지 않는다(정보 중복).
- 조장: 조원 현황 탭 위쪽에 "암송 시작일 [날짜] [저장]"을 둔다. 미설정이면 조장에게 안내 배너를 띄운다.

### 6.5 복습 (외운 뒤)
- 이번 주 탭 아래에 **[복습 1구절]**을 둔다. 복습할 때가 된 구절 중 가장 오래 기다린 것 하나만 기본으로 보여주고, 추가 복습은 선택이다. 밀린 개수나 실패 횟수는 강조하지 않는다.
- 같은 연습 카드로 주소부터 보여준다. 끝나면 **[복습 마치기]** 또는 **[내일 다시]**를 고른다.
  - [복습 마치기]: 간격이 다음 날 → 3일 → 7일 → 14일 → 이후 30일로 늘어난다(초기 운영값이며, 이 조원들에게 맞는지는 추정이다).
  - [내일 다시]: 짧은 간격으로 돌아간다.
- 저장은 localStorage에 **UID별 키**로 `{ [id]: { nextReviewOn, intervalStep } }`를 둔다.
  - 기록이 없으면 외운 날짜 다음 날을 첫 복습일로 한다.
  - 체크를 해제하면 복습 기록도 지운다. 기기를 바꾸면 복습 일정은 새로 시작한다.
- 복습 결과로 체크를 자동 해제하지 않는다.

## 7. 동기화·성능
- 조원 문서의 `memorized`가 바뀌면 기존 members 스냅샷이 들어온다. **실제로 표시값이 바뀐 화면만** 다시 그린다.
  - 조원 현황 탭, 조원 화면: 다시 그린다.
  - 연습 중: 연습 상태를 보존하며 다시 그린다.
  - 메인: 내 암송 진도나 주차 표시가 바뀔 때만 다시 그린다.
- 사본을 쓰면 `updatedAt`도 갱신되므로 조원 화면의 '최근 활동'에 반영된다. 의도된 동작이다.
